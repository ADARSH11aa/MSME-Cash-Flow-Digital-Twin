# MSME Cash-Flow Platform --- Design Document

**Document:** DESIGN.md\
**Status:** Implementation-ready\
**Primary audience:** Antigravity coding agent, frontend developers,
UI/UX designers\
**Product:** Consent-based MSME Cash-Flow Intelligence Platform\
**Design direction:** Premium financial SaaS + interactive 3D
storytelling

------------------------------------------------------------------------

## 1. Design Vision

Create a premium, trustworthy, modern financial SaaS website for MSMEs
that makes complex cash-flow intelligence feel understandable and
actionable.

The website should communicate:

> **See your cash flow before it becomes a problem.**

The visual experience combines:

-   Clean financial-product aesthetics
-   Strong editorial typography
-   Generous whitespace
-   Soft financial/technology visual language
-   Data-driven UI
-   Subtle glass and depth effects
-   Interactive 3D storytelling
-   Smooth scroll-driven motion
-   Clear trust and consent messaging

The website should feel **credible enough for finance**, but **modern
enough to feel like a next-generation technology product**.

Do not make it look like a generic banking website.

# 3. Product Design Principles

## 3.1 Trust First

Financial data requires trust.

The interface must clearly communicate:

-   Consent
-   Data control
-   Transparency
-   Explainability
-   Security
-   Correctability

Avoid exaggerated financial claims.

Do not use:

-   "Guaranteed profit"
-   "Guaranteed funding"
-   "Instant approval"
-   Fear-based messaging
-   Manipulative urgency

------------------------------------------------------------------------

## 3.2 Explain Complex Things Visually

The platform should visually explain:

**Business data → Cash-flow digital twin → Forecast → Insight → Action**

Do not rely on paragraphs to explain the product.

Use:

-   Animated diagrams
-   Charts
-   Flow visualizations
-   3D data structures
-   Interactive cards
-   Timeline animations
-   Before/after states

------------------------------------------------------------------------

## 3.3 Action Over Information

Every major analytical section should answer:

1.  What is happening?
2.  Why is it happening?
3.  What could happen next?
4.  What can the business owner do?

# 5. Visual Design System

## 5.1 Color Direction

Use a restrained financial technology palette.

### Base

-   Warm/off-white background
-   Near-black primary text
-   Soft neutral surfaces
-   Light gray borders

### Primary Accent

Use a sophisticated blue/indigo family to represent:

-   Trust
-   Intelligence
-   Technology
-   Financial stability

### Secondary Accents

Use restrained semantic colors:

-   Green → healthy / positive cash flow
-   Amber → attention / upcoming pressure
-   Red → risk / negative cash-flow event
-   Blue → information / forecast

Semantic colors must not dominate the entire interface.

------------------------------------------------------------------------

# 6. Typography

Use a modern sans-serif typeface.

Recommended characteristics:

-   High readability
-   Strong numerical legibility
-   Clean geometric shapes
-   Excellent variable-font support

Hierarchy:

### Display

Large, bold, short statements.

Example:

> Know your cash flow before it becomes a crisis.

### H1

Primary page statement.

### H2

Section-level narrative.

### H3

Feature/card titles.

### Body

Readable and relatively compact.

### Data

Use tabular/monospaced numerals where useful for:

-   Currency
-   Percentages
-   Dates
-   Forecast values

------------------------------------------------------------------------

# 7. Layout System

Use a responsive max-width container.

Recommended:

-   Desktop content width: approximately 1200--1400px
-   Large horizontal whitespace
-   12-column desktop grid
-   6-column tablet grid
-   4-column mobile grid

Use a consistent spacing scale.

Avoid random spacing values.

Major sections should have clear visual breathing room.

------------------------------------------------------------------------

# 8. Border Radius

Use moderately rounded surfaces.

Suggested system:

-   Small controls: 8--12px
-   Cards: 16--24px
-   Large feature panels: 24--32px
-   Hero container: 28--40px
-   Pills: 999px

Do not round every element excessively.

------------------------------------------------------------------------

# 9. Shadows and Depth

Use subtle depth.

Prefer:

-   Soft shadows
-   Low opacity
-   Layered surfaces
-   Blur only where useful

Avoid heavy drop shadows.

------------------------------------------------------------------------

# 11. Page Structure

## Page 1 --- Home

### Section 1: Hero

Purpose:

Immediately communicate the value proposition.

Headline direction:

> **See your business cash flow before it becomes a problem.**

Supporting text:

Explain that the platform turns consented business data into an
understandable cash-flow view, forecasts, and actionable
recommendations.

Primary CTA:

**Explore Your Cash Flow**

Secondary CTA:

**See How It Works**

### Hero visual

Do not use a generic phone mockup as the main visual.

Create a 3D **Cash-Flow Digital Twin**.

Concept:

A floating financial network representing:

-   Revenue
-   Expenses
-   Invoices
-   Inventory
-   Recurring costs
-   Upcoming obligations
-   Cash balance
-   Forecast

The network gradually transforms from raw transaction streams into an
organized cash-flow model.

------------------------------------------------------------------------

## Section 2: Problem

Headline:

> Cash flow problems rarely start when the cash runs out.

Show a timeline:

**Revenue → Expenses → Delays → Obligations → Cash Gap**

Use animated data cards and a flowing timeline.

------------------------------------------------------------------------

## Section 3: Product Explanation

Headline:

> Turn business data into a living cash-flow picture.

Show the product pipeline:

**Consent → Connect → Understand → Forecast → Act**

Use a horizontal animated flow on desktop.

On mobile, transform it into a vertical sequence.

------------------------------------------------------------------------

## Section 4: Digital Twin

This is a core differentiator.

Create an interactive visualization of a business's cash-flow digital
twin.

Components:

-   Current balance
-   Incoming cash
-   Outgoing cash
-   Recurring expenses
-   Receivables
-   Payables
-   Forecast horizon
-   Confidence indicator

The user should visually understand how multiple data sources become one
model.

------------------------------------------------------------------------

## Section 5: Forecast

Headline:

> Know what your next few weeks could look like.

Show:

-   Historical cash flow
-   Current position
-   Forecast region
-   Expected inflows
-   Expected outflows
-   Potential cash gap

Use an interactive animated chart.

Forecast area should visually differ from historical data.

------------------------------------------------------------------------

## Section 6: Explainability

Headline:

> Every insight should have a reason.

Example insight card:

**Cash pressure expected in 18 days**

Reason:

-   Two large supplier payments
-   Slower receivables
-   Recurring payroll obligation

Recommendation:

-   Review collection timing
-   Delay non-essential spending
-   Explore non-credit alternatives

The interface should allow users to understand why the system generated
an insight.

------------------------------------------------------------------------

## Section 7: Responsible Financial Guidance

Do not push users toward unnecessary borrowing.

Show a decision tree:

**Cash pressure detected** → Improve collections\
→ Reduce / reschedule expenses\
→ Use available savings\
→ Review public schemes / support\
→ Consider suitable financing only when appropriate

This section should visually reinforce responsible financial
decision-making.

------------------------------------------------------------------------

## Section 8: Features

Use 4--6 major feature cards.

Examples:

### Cash-Flow Overview

One clear view of business liquidity.

### Forecasting

Understand likely future cash positions.

### Explainable Insights

See why an insight was generated.

### Scenario Planning

Explore "what if" situations.

### Action Recommendations

Get practical next steps.

### Data Control

Control what data is connected and used.

------------------------------------------------------------------------

## Section 9: Scenario Simulator

Interactive section:

> What happens if your biggest customer pays 15 days late?

Allow scenario changes such as:

-   Payment delay
-   Revenue change
-   Expense increase
-   New recurring cost

Animate the cash-flow graph as the scenario changes.

This is a major opportunity for GSAP and interactive UI.

------------------------------------------------------------------------

## Section 10: Trust & Consent

Create a visually calm security section.

Show:

-   Consent-based data access
-   User-controlled connections
-   Explainable calculations
-   Correctable information
-   Secure processing
-   Transparent recommendations

Do not use exaggerated security claims unless technically verified.

------------------------------------------------------------------------

-   Central liquidity node
-   Incoming cash streams
-   Outgoing cash streams
-   Transaction nodes

## 3D Visual Language

Use:

-   Soft materials
-   Subtle reflections
-   Controlled lighting
-   Depth
-   Floating geometry
-   Thin connecting lines
-   Particle streams

Avoid:

-   Complex photorealistic environments
-   Heavy textures
-   Excessive bloom
-   High-poly assets
-   Constant camera movement

# 16. Animation Principles

Animations should communicate meaning.

### Hero

-   Text fades/slides in
-   3D digital twin assembles
-   Data streams begin moving

### Scroll

As user scrolls:

**Raw Data** → **Organized Data** → **Digital Twin** → **Forecast** →
**Insight** → **Action**

### Cards

Cards should reveal through:

-   Opacity
-   Small translation
-   Scale
-   Blur reduction

Avoid dramatic bouncing.

------------------------------------------------------------------------

# 17. Page Transitions

Use subtle transitions.

Recommended:

-   Fade
-   Vertical movement
-   Mask reveal

Do not make page transitions slow.

Target:

-   300--700ms for normal UI transitions
-   Longer only for cinematic hero transitions

------------------------------------------------------------------------

# 18. Hover Interactions

Buttons:

-   Small lift
-   Subtle scale
-   Background transition

Cards:

-   Slight elevation
-   Border highlight
-   Content reveal

3D elements:

-   Gentle parallax
-   Cursor response

Avoid excessive cursor effects.

------------------------------------------------------------------------

# 19. Responsive Design

## Desktop

Full experience:

-   Large 3D scenes
-   Scroll-driven animations
-   Multi-column layouts
-   Large typography
-   Interactive charts

## Tablet

-   Reduce 3D complexity
-   Simplify grids
-   Reduce typography
-   Preserve major animations

## Mobile

Prioritize:

-   Performance
-   Readability
-   Navigation
-   Core interactions

Reduce or disable:

-   Heavy 3D scenes
-   Large particle systems
-   Complex post-processing
-   Excessive ScrollTrigger effects

Use `prefers-reduced-motion`.

------------------------------------------------------------------------

# 20. Performance Requirements

Target:

-   Fast initial page load
-   Minimal JavaScript on static sections
-   Lazy-loaded 3D
-   Optimized assets
-   Code splitting
-   Responsive image loading
-   Efficient WebGL rendering

Use:

-   GLTF/GLB where appropriate
-   Compressed textures
-   Lazy loading
-   Suspense
-   Proper DPR limits
-   Reused geometries/materials
-   Instancing for repeated objects

Do not render 3D scenes that are not currently visible.

------------------------------------------------------------------------

# 21. Accessibility

Must support:

-   Keyboard navigation
-   Visible focus states
-   Semantic HTML
-   Proper heading hierarchy
-   Accessible buttons
-   Form labels
-   Sufficient contrast
-   Reduced motion
-   Screen-reader-friendly content

3D visuals must never be required to understand the product.

Every important 3D visualization must have a meaningful HTML
explanation.

# 30. Final Design Goal

The final website should feel like:

**A premium financial intelligence product from the future --- not a
template.**

The first impression should communicate:

> **We turn complex business cash flow into something you can see,
> understand, predict, and act on.**

The 3D experience should make the product memorable.
